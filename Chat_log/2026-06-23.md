# 2026-06-23 对话记录

## [下午] BC 感知特征修复（第二轮）

**任务**：修复专家演示录制中 `bifur_cx/cy` 始终为 0、depth 值偏大 100x 的两个 Bug。

**关键决策**：
- `bifur_cx/cy` 改用 `cav_sorted[0]`（最大腔道）而非依赖 `_cav_highlight_idx` — 原因：UI 高亮状态在未触发 'h' 键或无腔道时为 -1，导致 `l_cx/l_cy = None`，BC 注入写入 0；而 `bifur_area` 已经一直用 `cav_sorted[0]`，应保持一致。
- depth 注入由 `depth_m * 1000.0` 改为 `depth_m * 1000.0 * self.depth_scale` — 原因：DAV2 输出单位 m，系统标定系数 `depth_scale=0.01`，不加这个系数时深度值约 1000mm，实际应为 ~10mm，与 `OBS_FIELDS` 的归一化基准 300mm 严重不匹配。

**修改文件**：
- `2026/predict_2026_528_zck.py` 第 1000-1013 行 — bifur 特征改用 `cav_sorted[0]`，depth 乘以 `self.depth_scale`

**验证结果**：
- 重录测试文件 `20260623_165001_LMB_224frames.json` 验证通过：`bifur_cx=-0.17, bifur_cy=-0.38`（归一化坐标，设计如此），`depth_mean_mm=6.76mm` 正常。感知特征录制功能已完全修复。

**搁置决定**：
- BC 专家演示录制方案**暂时搁置**，原因：当前 YOLO 对支气管各部位及各岔口的识别精度不足，视觉特征的语义质量无法保证训练效果。
- **恢复条件**：待 YOLO 能够精准区分各支气管段（LMB/RMB/LUB/LLB 等）及各岔口后，再重新批量录制并启动 BC 训练。

## [上午/延续自昨日] BC 感知第一轮 Bug 修复

**任务**：查明所有视觉特征（depth、bifur、stone）全部为 0 的根本原因。

**关键决策**：
- 根因是 Python 模块别名问题：`predict_2026_528_zck.py` 原先用 `from data_collector import ...`（模块键 `"data_collector"`），主程序用 `from BC.data_collector import ...`（模块键 `"BC.data_collector"`），两个线程各持一个独立 `_visual_features` 字典，写入与读取不共享。
- 修复方案：将 `predict_2026_528_zck.py` 中的导入改为 `from BC.data_collector import update_visual_features`，确保两者用同一模块实例。
