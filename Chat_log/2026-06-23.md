## [下午] BC 感知特征修复（第二轮）

**任务**：修复专家演示录制中 `bifur_cx/cy` 始终为 0、depth 值偏大 100x 的两个 Bug。

**关键决策**：
- `bifur_cx/cy` 改用 `cav_sorted[0]`（最大腔道）而非依赖 `_cav_highlight_idx` — 原因：UI 高亮状态在未触发 'h' 键或无腔道时为 -1，导致 `l_cx/l_cy = None`，BC 注入写入 0；而 `bifur_area` 已经一直用 `cav_sorted[0]`，应保持一致。
- depth 注入由 `depth_m * 1000.0` 改为 `depth_m * 1000.0 * self.depth_scale` — 原因：DAV2 输出单位 m，系统标定系数 `depth_scale=0.01`，不加这个系数时深度值约 1000mm，实际应为 ~10mm，与 `OBS_FIELDS` 的归一化基准 300mm 严重不匹配。

**修改文件**：
- `2026/predict_2026_528_zck.py` 第 1000-1013 行 — bifur 特征改用 `cav_sorted[0]`，depth 乘以 `self.depth_scale`

**验证结果**：
- 重录测试文件 `20260623_165001_LMB_224frames.json` 验证通过：`bifur_cx=-0.17, bifur_cy=-0.38`（归一化坐标，设计如此），`depth_mean_mm=6.76mm` 正常。感知特征录制功能已完全修复。

**搁置决定**：
- BC 专家演示录制方案**暂时搁置**，原因：当前 YOLO 对支气管各部位及各岔口的识别精度不足，视觉特征的语义质量无法保证训练效果。
- **恢复条件**：待 YOLO 能够精准区分各支气管段（LMB/RMB/LUB/LLB 等）及各岔口后，再重新批量录制并启动 BC 训练。

2. 新建 `2026/AutoNav/` 模块，实现基于已录制纯电机序列的三层自主导航架构。

**关键决策**：
- **stone → obstruction 重命名策略**：只改 `BC/` 模块内的字段名和代码符号（`model.py`, `data_collector.py`, `inference.py`, `bc_main.py`, `verify_demos.py`）；旧版 JSON 文件自动兼容（`dataset.py` 的 JSON 加载器读取文件内的 `obs_fields` 字段来决定列顺序，旧文件不受影响）。

3. 修正 `PLAYBACK_SPEED` 默认值以适配 60Hz 主循环节拍（演示在 20Hz 录制）。

**关键决策**：
- **`PLAYBACK_SPEED` 从 1.0 改为 0.33** —— 原因：演示在 20Hz 录制，主程序控制循环为 60Hz（`busy_maintain_target_frequency(60, t0)`）。保持录制时电机角速度，缩放比 = 20/60 ≈ 0.33。`config.py` 中新增 `CONTROL_LOOP_HZ=60.0` 常量并保留 `TARGET_HZ=20.0`，方便后续按目标频率调速。`_AI_CMD_INTERVAL=3`（每 3 帧发一次串口，60Hz→20Hz）也佐证了 20Hz 是合理的指令频率。
- **替换策略选"替换 BC 推理"而非"新增并列 AI 模式"** —— 原因：AutoNav 与 BC 推理功能等价（都是自主巡检），但 AutoNav 不依赖训练模型，可以独立工作。BC 模型本来也只是备选方案，集成后保留 `BCRunner` 代码不动，便于回退。
- **集成粒度** —— 新增 `self._autonav` 懒加载实例，新增 `_stop_autonav()` 工具方法。`_transition_to_ai_auto` 在切换 `goal_id` 时同时清空 AutoNav（`self._autonav = None`），让下次进入时按新目标重启。BC runner 的代码逻辑全部保留以备回退。
- **测试覆盖**：

  - `test_autonav_integration.py`：模拟主循环的 5 阶段（启动→导航→注入阻塞物→清除→恢复→岔口引导→停止）共 11 个 PASS。
  - 集成测试 Phase 1 中修复了一个不合理的预期：30 帧只能推进 ~11°（LMB 平均轨迹 1.13°/step × 0.33 速度 = 0.37°/帧，30 帧 ≈ 11°），原测试预期 50° 是错误的。
