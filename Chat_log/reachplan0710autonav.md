# ReachPlan0710AutoNav：Layer 1 总结与后续分层计划

更新时间：2026-07-10  
统一入口：`2026/main2026-Xhandwriting-AC-AutoNav(0710)-Bronchus.py`

## 1. 项目目标

机器人从固定起点自主导航至主要支气管部位；Layer 2 使用岔口几何中心实时修正路线；Layer 3 发现阻塞物后暂停导航、追踪清除、返回最近断点并继续巡检。

实施顺序：

1. Layer 1：纯电机动作序列导航。
2. Layer 2：动作序列叠加岔口修正。
3. Layer 3：阻塞物清除和断点续航。
4. 三层联合全路径巡检。

当前结论：**Layer 1 已上机验证成功，能够按照具体采集文件到达指定部位的大概位置；现场重新采集—保存—立即导航闭环也已验证成功。**

## 2. 数据目录

- 历史数据：`2026/BC/expert_demos/BCdatasets/`，当前不使用。
- AutoNav 数据：`2026/BC/expert_demos/AutoNavdatasets/`。
- 同一部位可保存多条路径，UI 按具体 JSON 文件选择，不做均一化或自动平均。
- TR 不使用 JSON，采用独立三轴归零逻辑。

文件名格式：

```text
YYYYMMDD_HHMMSS_<部位代码>_<帧数>frames.json
```

Layer 1 使用每帧 `timestamp`、`m0_angle`、`m1_angle`、`m2_angle`；视觉字段继续保留给后续训练和 Layer 2/3 分析。

## 3. Layer 1 最终控制方法

### 3.1 单条路径直接导航

选定具体 JSON 后，从当前固定起点叠加该文件的原始相对角度轨迹。当前阶段不训练模型，不对同一部位的多条轨迹求平均。

### 3.2 原始时间和幅度还原

- 直接读取 JSON 绝对角度，不依赖 delta 近似累加。
- 按原始时间戳重建 60 Hz 导航目标。
- `PLAYBACK_SPEED=1.0` 表示采集时的真实节奏。
- 修改速度只改变持续时间，不改变最终位移。
- 瞬时变化触发单步限幅时，时间轴结束后继续追赶剩余角度，避免幅度丢失。

### 3.3 最终到位等待

路径指令结束后进入 `SETTLING`：保持最终目标并刷新真实三轴角度，进入容差后才完成。

- M0 容差：3°。
- M1 容差：2°。
- M2 容差：3°。

导航位置模式最大速度：M0=80°/s、M1=30°/s、M2=80°/s。

### 3.4 运行保护

```python
self._AI_MAX_STEPS = 10000
```

该值只限制异常情况下的最长运行，不参与方向和位置编码。

## 4. TR 固定原点

TR 已完全脱离 AutoNav：

- 独立状态 `ReturnOrigin`。
- 不创建 AutoNavController。
- 不调用 SequencePlayer。
- 不读取 path_label=1 文件。
- 直接闭环控制 M0/M1/M2 至 `(0°, 0°, 0°)`。

UI 选择 TR 或语音“回到起点”均进入该逻辑。START、B、LB 可中途停止。

## 5. 关键问题与修复日志

### 5.1 视觉输入 None

主程序曾误把视觉写接口当作读接口，导致 `visual.get()` 报错。现改用 `get_visual_features()`，并在控制器中把无效视觉输入按空字典处理。Layer 1 可在无视觉数据时独立运行。

### 5.2 动作幅度偏小

旧实现假设恒定 20 Hz、速度比例不准确、位置模式速度过低，并在电机追上终点前停止。现已改为原始时间戳、原始绝对角度、合理速度上限和最终到位等待。

第一条 LMB 离线核对：

```text
原始终点位移：[-158, 0, -91]°
导航终点位移：[-158, 0, -91]°
原始持续时间：11.0291 s
60 Hz 导航步骤：663
```

### 5.3 TR 被当作普通路径

早期 TR 会尝试加载不存在的 path_label=1。现增加独立 ReturnOrigin 状态，并在 AIAuto 中设置最终防线，任何 TR 入口均立即转入三轴归零。

### 5.4 LLB 超过约 1200 步后 M0 反向

根因位于 `Interface/RmdInterfaceV2.py`：A4 的32位多圈位置字段被固定按16位负数编码，目标低于 -327.68° 后溢出为正角度。例如 -360° 被错误发送为 +295.36°。

当前修复：

- 4位字段按16位补码编码。
- 8位字段按32位补码编码。
- 超出字段范围时抛出 OverflowError。
- `test_rmd_signed_encoding.py` 覆盖 -327°、-328°、-360°、-434°、-539°。
- 3项协议单元测试全部通过，LLB 上机验证成功。

### 5.5 LUB 原始数据包含回撤

`20260710_153920_LUB_504frames.json` 本身包含 M0 回撤：中段约28°、尾段约16°。这是采集动作，不是协议问题。后续如要求正常导航中 M0 严格单调前进，可只对 Layer 1 的 M0 应用累计最小值包络，不能影响 TR 和 Layer 3 返回断点。

## 6. 现场路径采集

恢复原因：纯动作导航依赖起点和装配相对位置；位置变化后必须允许现场重新采集。

当前 UI 流程：

1. 滚动到 UI 最底端“现场路径采集”。
2. 选择 TR 以外的目标部位。
3. 点击“开始采集”，程序停止旧导航并自动进入手动模式。
4. 使用手柄或 UI 从固定原点介入目标部位。
5. 到达后短暂保持，点击“结束并保存”。
6. 文件保存到 `AutoNavdatasets`。
7. 导航下拉菜单自动刷新，不需要重启。
8. 新文件可立即用于 Layer 1 验证。

保护逻辑：

- TR 和 EXP 不能采集。
- 当前采集未结束时禁止开始导航。
- 少于10帧的数据丢弃。
- UI 显示采集状态和最终文件名。

现场注意事项：

- 每条路径必须从相同固定起点开始。
- 动作连续、平稳，避免无意回撤。
- 到达目标后不要在结束采集前向外拉 M0，否则回撤会被保存。
- 同一部位允许多条文件，导航时必须确认具体文件名。

## 8. Layer 2 测试计划

前置条件：使用已验证安全的短路径，建议 LMB；Layer 3 保持关闭。

### 8.0 当前已知问题：远距离岔口修正可能放大路径偏差

> 本节保留最初发现问题时的分析记录。当前阶段的实施范围已按 8.3 收窄：只选择离画面中心最近的岔口，并用有限总偏置修正；暂不做未来路径匹配。无限累积、中心死区和候选选择问题已在 8.3 修复。

上机观察发现，岔口图像引导与真实电机随动方向、幅度不一定完全一致。当机器人画面中心与岔口几何中心距离较大时，当前视觉辅助可能持续输出较大的 M1/M2 修正，并逐帧累积到 Layer 1 原始动作目标中，结果不是温和地回到腔道中心，反而可能明显偏离原始安全路径。

当前风险来源：

- 尚未完成 M1/M2 图像方向与真实电机方向的逐轴标定。
- 没有中心误差死区，轻微噪声也可能持续修正。
- 没有“大偏差禁止修正”或可信范围门控；目标中心很远时仍直接介入。
- 修正量按帧累积，持续偏差可能形成越来越大的路径偏置。
- 面积权重只能描述候选区域大小，不能证明当前最大岔口就是原始路径计划进入的岔口。
- 当前未根据 Layer 1 未来动作方向选择最匹配的岔口。
- 未使用真实电机跟随误差限制下一帧视觉修正，电机尚未完成上一修正时可能继续叠加。

处理决定：**暂缓提高 Layer 2 增益，不进入完整路径联合测试。后续先修复控制结构，再继续 Layer 2。**

后续修复方向：

1. 逐轴标定 `bifur_cx/bifur_cy → M1/M2` 的真实正负方向。
2. 设置中心死区，岔口中心已接近画面中心时不再修正。
3. 设置最大可信偏差；中心距离过大时不直接纠偏，保持 Layer 1 或暂停等待重新识别。
4. 将修正从无限累积增量改为相对 Layer 1 基准轨迹的有限偏置，并限制总偏置角度。
5. 根据原始轨迹未来 M1/M2 方向，从多个岔口候选中选择最匹配的目标，不再只取最大面积。
6. 引入真实电机跟随误差门控；上一修正未到位时限制新修正继续累积。
7. 对视觉中心和修正量增加连续帧确认、低通滤波和异常跳变抑制。

修复后的安全目标：Layer 2只能对 Layer 1进行小范围、可恢复、有限幅度的辅助修正，任何时候都不能覆盖原始路径的主要运动趋势。

### 8.1 先验证方向

| 岔口位置 | 视觉输出 | 预期 |
|---|---|---|
| 画面右侧 | `bifur_cx > 0` | M1 向右侧中心修正 |
| 画面左侧 | `bifur_cx < 0` | M1 向左侧中心修正 |
| 画面下方 | `bifur_cy > 0` | M2 向下方中心修正 |
| 画面上方 | `bifur_cy < 0` | M2 向上方中心修正 |

如果方向相反，先修改增益符号，不要先增大增益。

### 8.2 再调增益

```python
BIFUR_GAIN_M1 = 3.0
BIFUR_GAIN_M2 = 2.5
BIFUR_CENTER_DEADZONE = 0.08
```

### 8.3 2026-07-15 最近岔口有限偏置修复

本阶段按新的调试范围收窄为：只判断岔口，机器人头部中心默认等于画面中心；多个岔口候选中只使用几何中心离画面中心最近者。暂不根据 Layer 1 未来动作选择分支，也不启用阻塞物清除。

视觉脚本采用版本隔离：`predict_2026_528_zck.py` 保留为此前可工作备份，本轮 Layer 2 视觉修改只写入新建的 `predict_2026_715_zck.py`；AutoNav 主程序的 `video_processing()` 使用 715 版本。

已完成：

- 视觉端不再固定使用按面积排序的 `cav_sorted[0]`，而是计算每个候选几何中心到画面中心的欧氏距离并选择最近者。
- 最近候选使用绿色轮廓、绿色几何中心和 `AutoNav nearest` 字样显示，便于现场核对选择是否正确。
- 增加中心死区，几何中心已经接近画面中心时不再纠偏，避免识别噪声造成 M1/M2 抖动。
- 岔口输出从“每帧角度增量”改为“相对 Layer 1 当前目标的总角度偏置”。Layer 1 基础目标与最终控制目标分开保存。
- M1/M2 总偏置分别限制在 ±5° 内；即使同一个远偏岔口连续出现数百帧，也不会再无限累计并覆盖采集路径。
- Layer 3 默认关闭；在 `enable_obstruction=False` 时，即便视觉字典含有阻塞物检测结果，也不会切入清除状态。
- 新增 `test_layer2_nearest_junction.py`，覆盖最近候选、中心死区、修正方向、300 帧不累积和 Layer 3 关闭验证。

仍需现场验证：

- M1 的左右正负方向是否与图像一致。
- M2 的上下正负方向是否与图像一致。
- ±5° 总偏置对实体机器人是否合适；首次只做短路径低风险测试。
- 电机真实随动误差是否需要额外门控。

### 8.4 2026-07-15 末段近中心微调与视觉模式调整

- `predict_2026_715_zck.py` 默认视觉模式改为：`1=岔口`、`2=阻塞物`、`3=混合`，启动默认进入模式1。
- 模式1使用最近岔口驱动窗口2右下角四个方向圆；岔口目标较远时仍显示方向供人工核对，但不输出XY追踪速度。
- H 键手动切换高亮功能取消；每帧自动将离画面中心最近的岔口加粗高亮并作为唯一追踪目标。
- 岔口轮廓统一使用青色，不使用绿色；绿色保留给阻塞物和后续混合检测。
- Layer 2 增加双门控：路径进度必须达到 80%，且最近岔口归一化中心距离必须不超过 0.30。
- 门控关闭时岔口偏置严格为0，导航中前段和远距离岔口完全由 Layer 1 示教轨迹主导。
- 岔口微调只作用于 M1/M2；M0 始终等于 Layer 1 基础目标。视觉岔口模式的 `speed_FR` 也固定为0。

### 8.5 2026-07-15 将硬门控改为连续权重

现场反馈表明，`progress >= 0.80` 和 `distance <= 0.30` 的硬条件过于严格：路径前段完全没有辅助，图控模式也只有目标特别接近中心时才会运动。因此调整为：

- 路径进度不再决定开/关。起点保留 25% 的视觉权重，随后按二次曲线平滑增强，进度达到 80% 后为完整进度权重。
- `distance <= 0.30` 改为完整响应区，不再是最大允许距离。
- 中心距离从 0.30 增加到 0.75 时，距离权重从 1 线性衰减到 0；只有达到 0.75 后才停止视觉微调。
- （已在 8.6 撤销）曾尝试让715图控模式的 `speed_pt` 使用同一距离权重，但这会把远距离输出压到电机启动阈值以下。
- 总偏置限幅、中心死区和 M0 隔离保持不变，防止视觉重新覆盖示教轨迹。

### 8.6 2026-07-15 优先恢复独立图控岔口对准闭环

现场发现独立图控模式无法把画面中心对准岔口几何中心。定位结果：Layer 2 的距离保护权重被错误复用到了独立图控速度。距离约0.70时，M1原始最大输出12被压缩到约1.33，而主程序M1输入小于2时会停止，因此机器人表现为不动；距离达到0.75后速度直接归零。

修复决定：独立图控闭环与Layer 2导航辅助分开调参。

- 取消715图控 `cav_vx/cav_vy` 的距离权重乘法，恢复原先已能追踪的“像素误差越大速度越快”策略。
- 10像素中心死区内停止，防止终点附近反复漂移。
- M1/X无减速器且实测响应慢：误差刚离开死区时速度约5，45像素后达到最大12。
- M2/Y带减速器且实测响应快：近端从0.05开始，80像素后达到视觉输出8；主程序乘8后最大64 deg/s。
- M2实际停止阈值从5 deg/s降低到0.5 deg/s，使其能在中心附近继续慢速精调，只有进入10像素死区才真正停止。
- 保留原可工作参数的符号约定：X轴对 `center-target` 取反，Y轴保持同号。
- 窗口叠加 `TRACK/HOLD`、归一化距离和 `(vx,vy)`，用于现场核对视觉是否在输出、输出方向是否正确。
- 岔口模式继续固定M0速度为0，只闭环控制M1/M2。

在独立图控实机闭环验证通过之前，不以方向圆作为Layer 2导航方向正确的充分证据。

### 8.7 2026-07-15 图控方向与M2速度现场修正

- 现场确认目标在右、右侧指示圆变红时，M1却向左运动；将视觉入口 `HORIZONTAL_CLOCKWISE_SIGN` 从 `+1` 改为 `-1`。
- 该符号只作用于VisionControl的水平输入，不修改底层 `M1_DIRECTION_SIGN`，因此不影响手动控制和Layer 1示教导航。
- M2图控速度过快，将 `VISION_M2_SPD_SCALE` 从8降到4，即当前速度的50%，最大视觉速度约从64降至32 deg/s。
