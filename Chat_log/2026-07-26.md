- 再次启动 GUI 后显示“运动连接失败”。

- 右下角手动、停止、归零、设零和断电按钮无响应。

### 诊断结果

- 手柄连接与机器人串口连接已经在 GUI 中解耦。

- 机器人主运行时未成功完成串口初始化，因此：
  - `RobotRuntime.ready=False`
  - 底部电机相关按钮按照安全规则保持禁用
  - 手柄虽然显示连接，也不会向未就绪的机器人电机发出控制

### 今日处理

- 未盲目修改串口或绕过按钮禁用保护。
- 保留“机器人未就绪时不允许下发电机命令”的安全边界。

## 三、RULB 短行程与停车后无法继续确认

### 初始问题

- BI 很容易识别。
- RULB 很难识别。
- 从 RMB 分叉区进入 RULB 的实际行程很短。
- RULB 偶尔出现黄色候选，但操作者很快到达目标并停止 M0。
- 原逻辑只在 `motion_mode == forward` 时累计 RULB/BI 视觉证据。
- 一旦停车，所有候选证据冻结，无法补齐 RULB 所需命中次数。

### 第一轮：停车确认窗口

最初增加只针对 RULB 的停车确认窗口：

- 前进期间必须先出现 RULB 黄色候选。
- 必须已经存在弯曲证据。
- 停车后短时间内允许继续累计 RULB。
- BI 和其他部位停车时仍保持冻结。
- 静止状态不能凭空建立 RULB 候选。

最初窗口为 `1.5 秒`。

### 第二轮：延长窗口并保留稀疏证据

实机反馈仍然只有黄色，无法确认。

进一步发现：

- 停车阶段每个漏检周期仍会把 `False` 写入 6 帧窗口。
- 前进期间仅有的一次 RULB 黄色命中，很快被空帧挤出。
- 单纯延长时间不能解决稀疏识别。

因此改为：

- 停车确认窗口延长为 `3.0 秒`。
- 停车期间空帧不再冲掉已有 RULB 黄色证据。
- 只有再次真正看到 RULB 时才追加证据。
- 没有实际弯曲反馈时，停车确认由常规 3 次降为累计 2 次。

对应配置：

```python
rulb_idle_grace_seconds = 3.0
rulb_idle_required_hits = 2
```

## 五、M2 弯曲状态锁存

### 第二次现场反馈

- 即使加入 M2 实际角度，黄色 RULB 仍可能保持数秒后熄灭。
- 操作者说明弯曲动作完成后手柄回中，但物理弯曲持续存在。

### 最终弯曲状态规则

弯曲状态不再视为瞬时事件，而是锁存状态：

- M2 相对设零位置的绝对角度至少 `5°`，认为已经弯曲。
- 手柄发生过 M2 弯曲操作且存在 M2 位置反馈时，锁存弯曲状态。
- 手柄回中不会清除锁存。
- 只有 M2 回到零位附近 `±2°`。
- 并且连续稳定 5 个检测周期。
- 才释放弯曲锁存。
- 如果 M2 角度反馈缺失，则降级使用原来的短时弯曲记忆，不永久锁存。

当前配置：

```python
branch_bend_m2_position_threshold_deg = 5.0
branch_bend_release_position_deg = 2.0
branch_bend_release_frames = 5
branch_bend_memory_seconds = 1.0
```

注意：

- 实机测试前应在内窥镜基本伸直时执行一次“设为零位”。
- 如果在弯曲状态下设零，M2 角度无法正确表示相对直线位置。

## 六、M1 整体旋转是否参与 RULB 门控

### 用户疑问

- 操作 M1 旋转内窥镜整体角度后，RULB 识别表现发生变化。
- 怀疑 M1 是否被错误地当成 RULB 弯曲条件。

### 核对结果

手柄与电机映射：

- RT/LT：M0 前进/后退
- RX：M1 整体旋转
- LY：M2 上下俯仰

RULB 门控只使用：

- M0 前后状态和位置
- M2 实际角度
- M2 弯曲操作
- YOLO 的 RMB/RULB/BI 结果

M1 没有直接参与 RULB 状态门控。

M1 仍会间接影响模型：

- 改变摄像头视角。
- 改变弯曲尖端在空间中的朝向。
- 改变 RULB/BI 在画面中的形态和可见程度。

已增加测试，保证单独的 M1/horizontal 命令不会被计为弯曲信号。

## 七、尚未真正后退却过早识别为 TR

### 风险来源

原 `NapoleonMotorFeedbackAdapter` 在手动模式中：

- 只要检测到 M0 前进/后退命令；
- 即使 M0 真实速度尚未建立；
- 也会提前发布 `forward/backward`。

这会导致：

- 扳机微小噪声可能触发解剖状态回退。
- 命令刚下发但电机尚未运动时，状态机已经开始累计父节点。
- RMB 黄色候选可能被直接丢弃并开始走 RMB→TR。

### 修改

手动模式下运动状态现在必须满足：

1. M0 命令超过死区。
2. M0 真实速度超过反馈死区。
3. 命令方向与真实速度方向一致。

否则一律发布 `idle`：

```text
manual_command_waiting_feedback
manual_command_feedback_mismatch
manual_command_neutral
```

因此：

- 只有扳机命令、没有真实运动：不算前进/后退。
- 命令和缓存速度方向相反：不算前进/后退。
- 操作 M1/M2：不能触发 RMB→TR。

## 八、M2=500° 实机日志与强弯曲快速确认

### 用户提供的关键日志

```text
F=-100.0
M1=13.0°
M2=499.0° / 500.0°
电机02停在上限
```

### 解释

- `M2=499–500°`：实际已经处于非常强的弯曲状态。
- `F<0`：根据原 Napoleon 控制定义，代表 LT 后退。
- 因此此前一个可能的操作节奏是：
  1. RULB 黄色刚出现。
  2. 尚未来得及经历一次 YOLO 停止周期。
  3. 操作者立即按 LT 后退。
  4. 原分叉门控先看到 `backward`，丢弃黄色候选。
  5. 从仍确认的 RMB 开始回退，容易很快识别为 TR。

### 最终增加的规则

新增强弯曲阈值：

```python
rulb_strong_bend_m2_position_deg = 100.0
```

在 M2 强弯曲区：

- 一次 RULB 视觉命中即可在前进过程中确认。
- 不再等待常规 6 帧中 3 次命中。
- 仍要求：
  - 电机反馈有效
  - 前进状态已经完成运动唤醒
  - M0 从 RMB 锚点的前进距离不超过 RULB 上限

如果黄色候选出现后立即开始后退：

- 先提交已经到达的 RULB。
- 再按照：

```text
RULB -> RMB -> TR
```

逐级回退。

- 不再允许跳过 RULB 直接从黄色候选落到 TR。

当前强弯曲规则属于为现场操作节奏加入的较积极策略。模型重训完成后应重新评估是否仍需保持单帧快速确认。

5. 当前 RULB 仍不稳定的主要瓶颈已经转向模型和数据集，而不是继续缺少一个状态机条件。
6. 当前强弯曲单帧确认属于偏积极的临时补偿。由于 BI 假阳性较高，不能继续无条件放宽。

## 十五、下次工作的建议顺序

### 优先级 1：采集当前实机困难数据

使用当前 GUI 的录像功能采集完整连续视频：

- 尚未出现清晰气管的初始画面。
- TR→RMB。
- RMB 分叉处。
- 不同 M1 旋转角度。
- M2 从轻度弯曲到 500°强弯曲。
- RULB 清晰画面。
- RULB 与 BI 容易混淆的过渡画面。
- 从 RULB 回退到 RMB、TR。
- 贴壁、反光、模糊和暂时失焦。

建议同时保存时间戳对应的：

- M0 命令和真实速度
- M0/M1/M2 角度
- 原始 YOLO 类别和置信度
- 状态机 `reason`
- 分叉门控 `phase`

当前干净视频界面不显示置信度，但可在后续加入独立 CSV 诊断记录，不污染主画面。

### 优先级 2：重建数据集

- 加入大量空标签负样本。
- 将无明确部位和过渡帧设为空标签，不能强制标成 TR/BI。
- 增加 M2 强弯曲、不同 M1 旋转角度下的 RUL。
- 增加“看起来像 BI、实际是 RUL”的困难负样本。
- 增加“看起来像 RUL、实际是 BI”的困难负样本。
- 按完整视频/采集批次划分 train/val/test，避免相邻帧跨集合。

### 优先级 3：重新选择任务形式

当前每帧基本只有一个覆盖大画面的框，可评估：

1. 保留 YOLO 检测，但加入大量空标签帧。
2. 改为图像分类模型，并增加 `NONE/TRANSITION` 类。
3. 使用图像分类 + 时间窗口 + 解剖拓扑状态机。

不建议只更换更大模型而保持原数据结构不变；数据和标签策略优先于模型规模。

### 优先级 4：验收指标

下次不应只看总体 mAP，至少单独报告：

- RUL Recall
- RUL Precision
- BI 在背景/过渡帧上的假阳性率
- RUL→TR、RUL→BI 混淆率
- 按完整未见过视频统计的连续识别稳定性

建议目标：

- RUL Recall 至少达到 `80%`，再逐步争取 `85%+`
- BI 背景误检显著低于当前水平
- 未出现明确部位时允许输出“无检测”

### 优先级 5：运动连接

若下次仍显示“运动连接失败”：

- 先确认实际电机控制器串口。
- 不要因为手柄显示连接就假定机器人串口已经就绪。
- 保留机器人未就绪时按钮禁用和不下发电机命令的保护。
