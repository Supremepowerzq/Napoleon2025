## 一、全流程自主巡检轨迹拼接

### 目标

此前每条叶段轨迹均从 TR 原点单独出发。全流程巡检需要在开始执行前，把五条现场选择的轨迹拼成一条连续路径，并按照固定顺序依次巡检五个叶段。

### 路径顺序

```text
TR
 → LUB 左上
 → LLB 左下
 → RUL 右上
 → RML 右中
 → RLL 右下
 → TR 原点
```

顺序固定，但每个叶段使用的 JSON 轨迹可以在 UI 中重新选择，因此现场重新录制轨迹后不需要修改代码。

### 拼接方法

对每一对相邻叶段轨迹：

1. 读取两条轨迹的三轴累计电机角度：

```text
(M0, M1, M2)
```

2. 在角度空间中搜索重复点或近似重复点。
3. 当前叶段到达终点后，沿当前轨迹反向回退到公共点。
4. 如两个公共点不能完全重合，则插入短连接段完成对齐。
5. 从公共点继续沿下一条叶段轨迹前进。
6. 完成 RLL 后沿轨迹反向返回 TR 原点。

当前近似重复点参数：

```text
M0 容差：20°
M1 容差：12°
M2 容差：30°
最大归一化距离：1.5
```

全流程轨迹被划分为：

```text
forward       前往目标叶段
backtrack     沿已走轨迹回退到公共点
bridge        两条轨迹公共点之间的短连接
return_origin 最终返回 TR 原点
```

### 轨迹选择与规划界面

UI 最下方增加：

```text
全流程自主巡检设定（顺序固定，轨迹可选）
```

功能包括：

- 五个叶段分别选择 JSON 轨迹文件。
- 点击“规划全流程”后，在后台验证轨迹并搜索四组公共点。
- 轨迹选择发生变化后，原规划自动失效，必须重新规划。
- 规划成功后提示：

```text
路径已规划完成：XXXX 步 / 4 个公共点，可以开始全流程自主巡检
```

- 未规划、轨迹无效或机器人不在 TR 原点时禁止启动。
- “开始全流程巡检”按钮宽度已增加到 200，避免文字显示不完整。

## 三、保守式 Layer 2 岔口图像修正

### 实验依据

现场经验表明：

- 当岔口几何中心距离画面中心较远时，图像追踪较难稳定追上。
- 如果此时给出较大修正，可能反而将已验证的 Layer 1 轨迹拉偏。
- 当画面中心与岔口几何中心已经比较接近时，图像模型适合做小幅实时微调。

因此本次没有让 Layer 2 接管导航方向，而是将其设计为 Layer 1 上的有限残差修正。

### 控制结构

```text
最终目标角度 = Layer 1 当前基础目标角度 + Layer 2 有限视觉偏置
```

Layer 2 偏置不会逐帧累积到轨迹中，因此不会持续覆盖或改变原始路径的大方向。

M0 前进轴完全使用 Layer 1。

Layer 2 只修正：

```text
M1：左右方向
M2：上下方向
```

### 生效条件

Layer 2 同时满足以下条件才允许介入：

1. UI 中明确勾选“启用 Layer 2 近中心微调”。
2. 当前处于 `forward` 前进段。
3. 图像中检测到有效岔口候选。
4. 候选面积达到可信阈值。
5. 岔口中心处于画面中心附近。
6. 候选位置连续稳定至少 4 帧。
7. 相邻候选中心跳变不超过 0.12。
8. 视觉共享数据更新时间不超过 0.25 秒。

以下阶段强制关闭 Layer 2，严格执行 Layer 1：

```text
backtrack
bridge
return_origin
```

视觉超时、检测丢失、数据异常、候选跳变或中心距离过远时，也立即清除视觉偏置并返回纯 Layer 1。

### 当前保守参数

```text
中心死区：0.08

中心距离 <= 0.12：
    使用完整距离权重

中心距离 0.12 ~ 0.35：
    修正权重线性减弱

中心距离 >= 0.35：
    完全停止图像修正

连续稳定帧：4
视觉最大允许延迟：0.25 s
最大候选跳变：0.12

M1 增益：2.0
M2 增益：1.5
M1 最大总偏置：±2.0°
M2 最大总偏置：±1.5°
EMA 响应系数：0.25
```

修正强度还会结合当前前进叶段的局部执行进度平滑变化，避免在叶段开始时突然介入。

### 岔口候选

视觉线程不再默认使用面积最大的腔道候选，而是选择：

```text
几何中心距离画面中心最近的候选
```

## 四、视觉共享链路修复

### 问题

视觉预测线程通过：

```python
from BC.data_collector import update_visual_features
```

写入岔口特征，主控制器通过同一模块读取共享快照。

检查发现 `BC/data_collector.py` 内部仍使用旧式：

```python
from model import ...
```

在仅将 `2026` 目录加入 Python 路径的启动方式下，这可能导致包导入失败。预测线程会进入兼容分支并静默禁用视觉特征写入，从而出现“UI 已开启 Layer 2，但控制器没有视觉数据”的风险。

### 修改

改为优先使用包内相对导入：

```python
from .model import ...
```

同时保留直接在 BC 目录运行旧脚本时的 `from model import ...` 兼容分支。

视觉线程每帧写入：

```text
bifur_detected
bifur_cx
bifur_cy
bifur_area
visual_timestamp
```

`visual_timestamp` 使用单调时钟，控制器据此判断视觉线程是否停更。

## 十一、图控模式左右方向修复与快捷按钮调整

### 现场现象

- 独立图控模式最初左右追踪正常，随后出现左右方向相反。
- 同时核对 UI 第一排紫色“AI巡检”和灰色“自动模式”的实际功能。

### 原因

视觉算法使用统一语义：

```text
目标位于画面右侧 → vx > 0
目标位于画面左侧 → vx < 0
```

但主程序在进入 M1 控制前执行了：

```python
horizontal_input * HORIZONTAL_CLOCKWISE_SIGN
```

当时：

```python
HORIZONTAL_CLOCKWISE_SIGN = -1.0
```

而 `map_horizontal()` 内部还会使用底层 `M1_DIRECTION_SIGN` 统一处理实际电机方向。视觉入口后来增加的 `-1` 使图控输入与手动控制输入的正负语义不再一致，最终造成左右追踪相反。

### 修改

图控入口不再额外反号：

```python
HORIZONTAL_CLOCKWISE_SIGN = 1.0
```

现在：

- 视觉算法只负责输出目标相对画面中心的方向。
- 图控和手动控制使用相同的水平输入正负语义。
- 实际电机安装方向仍只由 `map_horizontal()` 内的 `M1_DIRECTION_SIGN` 统一处理。
- 不修改 Layer 1、全流程 AutoNav 或 Layer 2 的角度偏置方向。

紫色“AI巡检”按钮最终保持原功能：

```text
AI巡检 → ai_auto → AIAuto
```

`AIAuto` 最初设计时用于 BC 模仿学习 `BCRunner`，但当前活动主程序已经用 `AutoNavController` 替换原 `BCRunner`，因此该按钮目前实际进入轨迹回放式 AutoNav，而不是调用模仿学习 checkpoint。此次只恢复并保留现有入口，没有改动其控制链。

灰色“自动模式”按钮继续进入：

```text
自动模式 → vision → VisionControl
```

为便于区分，按钮背景改为浅蓝色：

```text
普通：#81D4FA
悬停：#4FC3F7
按下：#29B6F6
```

下方“开始自主导航”和“开始全流程巡检”入口不受按钮颜色和快捷入口调整影响。

- 当机器人逐渐靠近阻塞物；
- 阻塞物面积达到画面的约 1/3 以上；
- 独立图控模式可以较好地自主追踪并对准阻塞物。

该结果说明当前阻塞物分割与近距离图控闭环在目标占比较大时具备良好的功能性效果。尚未对更小面积目标的捕获距离和成功率做定量统计。

### 切换模式时弹出灰色空窗

实际显示视频的 OpenCV 窗口名称为：

```text
BronchMap | Original | UNet | Depth | 3D
```

但原键盘 1/2/3 切换代码对另一个不存在的窗口名称调用：

```python
cv2.setWindowTitle(
    "Combined View: Original | UNet | Depth | 3D PointCloud",
    ...
)
```

OpenCV 因此生成了一个没有画面内容的灰色窗口。

处理方法：

- 删除模式切换过程中的 `cv2.setWindowTitle()`。
- 模式名称继续直接绘制在现有视频画面左下方。
- 不创建第二个 OpenCV 窗口。

### UI 三模式切换

在整个 Tk UI 最底端增加三个小按钮：

```text
1 岔口
2 阻塞物
3 混合
```

对应：

```text
Mode 1：岔口追踪
Mode 2：阻塞物追踪/清除
Mode 3：阻塞物优先混合追踪
```

键盘和 UI 通过根目录 `config.py` 中新增的持久、加锁状态共享当前模式：

```python
set_tracking_mode(mode)
get_tracking_mode()
```

该状态与原速度指令的单生产者/单消费者队列分离，允许：

- Tk UI 写入模式。
- OpenCV 键盘写入模式。
- 视觉线程每帧读取模式。
- 在视觉线程启动前先通过 UI 选择模式。
