#### DepthPathFinder 算法细节
- 将深度图分割为 3×5 区域网格
- 提取左/中/右三列深度均值作为路径分析特征
- 检测深度阈值突变区域，判断是否到达岔口
- 反应式视觉模式下直接驱动位置控制器；AI 模式下作为观测特征

### 3. 20维结构化观测向量
```
视觉特征 (7维):
  stone_cx / stone_cy        — 黏液质心归一化坐标
  stone_area                 — 黏液面积占比
  stone_detected             — 是否检测到黏液 (0/1)
  bifur_cx / bifur_cy        — 岔口质心归一化坐标
  bifur_area                 — 岔口面积占比

深度特征 (6维):
  depth_center_mm            — 图像中心深度
  depth_mean_mm              — 管腔平均深度
  depth_max_mm               — 95百分位深度
  path_left_mm               — 左侧路径深度
  path_center_mm             — 中间路径深度
  path_right_mm              — 右侧路径深度

电机位置 (3维): m0 / m1 / m2 (归一化)
电机速度 (3维): dm0/dt, dm1/dt, dm2/dt (归一化)
时间步长 (1维): dt / 0.05 (20Hz→1.0)
```

### 5. 目标条件化策略网络 (BronchusPolicy)

**网络架构:**
```
输入: obs_seq [B, T=8, 20] + goal_id [B]
  │
  ├─ ObsEncoder (MLP 20→128→128, LayerNorm+ELU)
  ├─ GoalEmbedding (Embedding 10→16, broadcast to T frames)
  │
  ├─ concat → [B, T, 144]
  │
  ├─ GRU (2层, hidden=256, dropout=0.1)
  │    └─ last hidden → [B, 256]
  │
  ├─ Action Head (MLP 256→128→3, Tanh)  → Δ[m0, m1, m2] ∈ [-1,1]
  └─ Task Head  (MLP 256→64→2)          → logits(navigate, clear)
  
参数量: ~0.4 M
```

**10 个目标支气管标签:**
```
0: EXP — 自主探索       5: LLB — 左下叶
1: TR  — 气管           6: RUL — 右上叶
2: LMB — 左主支气管     7: BI  — 中间支气管
3: RMB — 右主支气管     8: RML — 右中叶
4: LUB — 左上叶         9: RLL — 右下叶
```

### 6. BC 训练流程
- 数据格式：HDF5（h5py），压缩存储，支持高效随机访问
- 采集频率：20 Hz，每帧记录完整 20 维观测 + 路径标签 + 子任务标签
- 损失函数：MSE(动作) + 0.3 × CrossEntropy(子任务分类)
- 优化器：AdamW，CosineLR，AMP 混合精度，EarlyStopping(patience=30)
- 验证划分：90/10 train/val
- TensorBoard 监控训练曲线

### 7. 实时推理
- `BCRunner`：滑动窗口 FIFO buffer (T=8)，线程安全特征读取
- 推理延迟：<5 ms（RTX 3090），满足 20 Hz 闭环
- 输出动作经缩放后通过位置控制接口下发给三个电机

### 8. 语音交互
```
支持指令:
  "切换为自主模式"  → Mode-4 AI-Auto
  "去左主支气管"   → AI-Auto + goal=LMB
  "去右主支气管"   → AI-Auto + goal=RMB
  "去右上叶"       → AI-Auto + goal=RUL
  (共 19 条中文指令)
```

## 二、主要创新点（论文用）

1. **多模态融合观测设计**：首次将 UNet 分割特征、Depth-Anything-V2 度量深度和 DepthPathFinder 路径分析输出融合为统一的 20 维结构化向量，同时覆盖视觉、几何、本体感知三类信息。

2. **目标条件化 GRU 策略**：goal token 设计允许单一网络通过嵌入向量区分 10 个解剖目标，避免为每条路径训练独立策略，泛化性更强。

3. **双头网络 + 子任务分类**：导航和清理共用时序编码器，子任务头提供显式监督，改善两种操作阶段的动作质量。

4. **完整系统集成**：从硬件驱动到感知到策略到语音 UI，所有模块在同一进程、20 Hz 闭环运行，系统工程贡献。
