# Latency Benchmark Reference

## 1. 本次离线测得结果（RTX 4090）

- UNet: 27.08 ms ± 8.02
- YOLO: 7.16 ms ± 0.23
- DepthAnythingV2: 62.27 ms ± 0.47
- BC GRU 推理: 0.91 ms ± 0.06

### 1.1 说明

- 当前可用模型权重和图像输入已在本地验证通过。
- 这组数据反映了离线 `inference_only` 情况，不包含相机采集、图像预处理、融合、命令发送或电机响应延迟。
- 由于 DepthAnythingV2 是当前系统中最耗时的模块，Depth 部分是整体延迟瓶颈。

## 2. 合理参考范围区间（RTX 4090/同级 GPU）

| 模块 | 良好范围 | 可接受范围 | 说明 |
|---|---|---|---|
| UNet | 20–30 ms | 15–40 ms | 27 ms 左右属于正常，若精度允许可优化至 20 ms 以下。 |
| YOLO | 6–10 ms | 5–15 ms | 7 ms 表现良好；低于 10 ms 是实时检测常见水平。 |
| 深度 | 55–70 ms | 45–85 ms | 60 ms 左右是 DepthAnythingV2 Metric 版本在 518×518 输入下的典型测量值。 |
| BC GRU | 0.6–1.5 ms | 0.5–3 ms | 小于 1 ms 表明策略推理几乎不会成为主瓶颈。 |

## 3. 合理的良好实验结果与趋势

### 3.1 期望趋势

- `Depth` 模块是最明显的瓶颈，优化空间最大。
- `YOLO` 和 `BC` 延迟已经很小，优先保证精度后再做微调。
- `UNet` 处于中等开销，若整体延迟需要下降，可通过轻量化 backbone、裁剪输入或降低分辨率优化。
- 整体推理路径趋势应为：`Depth > UNet > YOLO > BC`。

### 3.2 目标结果

- 如果目标是实时控制，离线推理总时延应保持在约 90–110 ms 左右。若包含相机采集和系统开销，完整控制周期可接受范围为 110–160 ms。
- 控制频率目标：10 Hz（100 ms）或更高。若每帧延迟稳定在 120 ms 左右，仍可实现 8 Hz 控制。
- 结合摄像头与命令发送，端到端闭环建议不超过 150 ms；若能降到 100 ms 左右则更稳。

### 3.3 实验趋势判断

- 若一组优化方案使 Depth 延迟降低 10–15 ms，同时 UNet/YOLO/BC 变化不大，则该方案是有效的。
- 若 UNet 下降但 Depth 持平，说明视觉分割优化已成功，整体改进有限；此时需考虑是否可以进一步压缩 Depth 模型。
- 若 YOLO 延迟增长而整体性能未明显提升，说明目标检测已不是主瓶颈，应回退到更快权重。
- 若 BC 延迟显著高于 2 ms，则说明模型或 GPU 上下文管理存在问题，要检查批次、锁或 cuda 同步调用。

## 4. 不能直接补全的集成阶段建议

以下阶段目前未直接测量，但可作为后续实测参考：

- 相机采集与图像预处理：10–20 ms
- 结构感知/UNet 输入准备：5–15 ms
- 解剖分割/YOLO 前处理：5–10 ms
- 融合/控制命令生成：5–15 ms
- 命令发送：1–5 ms
- 电机响应/ack：10–30 ms

如果后续集成实验中 `control_period_ms` 显著高于 150 ms，应优先从 Depth 和相机采集链路查起。

## 5. 建议的实验判据

- 目标：离线感知+控制推理总时延 ≤ 120 ms；若实际闭环包含传感器与总线开销，目标为 ≤ 150 ms。
- 最好观察 p90 和 p95；如果 p95 超过 150 ms，即使均值低也可能出现不稳定。
- 若整体延迟下降但成功率或定位精度下降，应优先保留精度，延迟优化仅作为第二阶段。
