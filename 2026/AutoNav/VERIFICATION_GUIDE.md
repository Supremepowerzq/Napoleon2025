# AutoNav 系统验证指南

**版本：1.0 | 日期：2026-07-10**

本文档描述 AutoNav 三层架构的完整验证流程，包括**离线测试**和**上机验证**两个阶段。

---

## 验证总览

| 阶段 | 内容 | 依赖 | 预计耗时 |
|------|------|------|----------|
| **离线测试** | 纯逻辑单元测试，无需机器人 | 无 | 30 分钟 |
| **上机 Layer 1** | 纯序列导航，无视觉 | 演示数据 | 2 小时 |
| **上机 Layer 2** | 岔口识别 + 路线修正 | Layer 1 通过 | 2 小时 |
| **上机 Layer 3** | 阻塞物追踪 + 断点续航 | Layer 1+2 通过 | 3 小时 |
| **完整巡检** | 三层联合 + 全路径覆盖 | 全部通过 | 4 小时 |

## 第二阶段：上机验证

> **重要**：上机验证前，确保机器人处于安全状态，紧急停止按钮可用。

### Layer 1 验证：纯序列导航

**目标**：验证机器人能从固定起点自主到达目标部位

**步骤**：

1. **准备阶段**
   - 将机器人回零到初始位置
   - 记录初始电机角度 (m0, m1, m2)
   - 选择测试路径（如 LMB，path_label=2）

2. **低速验证**（`PLAYBACK_SPEED = 0.8`）
   ```python
   # 在主程序中设置
   from AutoNav.config import PLAYBACK_SPEED
   PLAYBACK_SPEED = 0.8  # 比原始采集节奏慢 20%
   ```
   - 观察机器人是否沿预期路线前进
   - 记录最终到达位置
   - 对比预期终点与实际终点

3. **原始节奏验证**（`PLAYBACK_SPEED = 1.0`）
   - 逐步提速，观察运动平滑性
   - 检查是否有抖动或卡顿

4. **验收标准**

   | 指标 | 合格标准 | 测量方法 |
   |------|----------|----------|
   | 到达精度 | 终点误差 ≤ 10° | 记录终点电机角度对比演示数据 |
   | 运动平滑 | 无明显抖动 | 目视观察 |
   | 壁碰次数 | 0-2 次 | 记录壁碰事件 |
   | 耗时 | 与演示时长比例合理 | 计时对比 |

**增益调节**（如需要）：
- 若机器人偏向一侧 → 调整初始角度偏移
- 若速度不稳 → 微调 `PLAYBACK_MAX_DELTA`

---

### Layer 2 验证：岔口识别 + 路线修正

**目标**：验证岔口识别能有效减少壁碰

**步骤**：

1. **确认视觉功能**
   ```python
   # 检查视觉输出
   vis = get_visual_features()
   print(f"bifur: cx={vis.get('bifur_cx')}, cy={vis.get('bifur_cy')}, area={vis.get('bifur_area')}")
   ```
   - 确认 `bifur_area > 0.01` 时岔口被识别
   - 多个岔口出现时，确认绿色 `AutoNav nearest` 标记位于离画面中心最近的岔口
   - 确认 `bifur_cx/cy` 方向正确

2. **方向验证**（关键）
   ```python
   # 临时测试脚本，观察修正方向
   from AutoNav.junction_guide import JunctionGuide
   jg = JunctionGuide()
   
   # 场景1：岔口在右侧
   corr = jg.compute_correction(bifur_cx=0.5, bifur_cy=0.0, bifur_area=0.05)
   print(f"Right: m1 correction = {corr[0]:.3f}")  # 应为正值
   
   # 场景2：岔口在左侧
   corr = jg.compute_correction(bifur_cx=-0.5, bifur_cy=0.0, bifur_area=0.05)
   print(f"Left: m1 correction = {corr[0]:.3f}")  # 应为负值
   ```

3. **上机测试**
   - 从固定起点出发
   - 进入岔口区域时观察修正方向
   - **若方向相反**：修改 `config.py` 中 `BIFUR_GAIN_M1`/`BIFUR_GAIN_M2` 的正负号

4. **增益调节**

   | 现象 | 调整策略 |
   |------|----------|
   | 修正不足，仍碰壁 | 增大 GAIN（如 3.0 → 5.0） |
   | 修正过度，抖动 | 减小 GAIN/最大偏置，或减小 `BIFUR_RESPONSE_ALPHA` |
   | 方向相反 | 改 GAIN 符号（+ → - 或 - → +） |
   | 远离岔口时误修正 | 增大 `BIFUR_AREA_THRESHOLD` |

5. **验收标准**

   | 指标 | 合格标准 | 测量方法 |
   |------|----------|----------|
   | 岔口识别率 | 目标岔口 > 90% 被识别 | 记录识别事件 |
   | 壁碰减少率 | Layer 2 开启后壁碰减少 ≥ 50% | 对比开关修正 |
   | 修正延迟 | 修正响应 < 3 帧 | 帧级记录 |

---

### Layer 3 验证：阻塞物追踪 + 断点续航

**目标**：验证检测到阻塞物后能追踪清除并恢复导航

**步骤**：

1. **确认视觉功能**
   ```python
   vis = get_visual_features()
   print(f"obstruction: detected={vis.get('obstruction_detected')}, "
         f"cx={vis.get('obstruction_cx')}, cy={vis.get('obstruction_cy')}")
   ```

2. **断点保存测试**
   - 启动自主导航到中途某点
   - 人为触发阻塞物检测（遮挡镜头或模拟）
   - 确认终端输出：`[ObstructionHandler] 断点已保存: 步骤=X`

3. **清除流程测试**
   - 确认模式切换：`CLEARING → RETURNING → NAVIGATING`
   - 观察追踪是否指向阻塞物中心
   - 阻塞物消失后是否正确切换

4. **续航恢复测试**（关键）
   - 完成清除后确认：
     - 机器人回到断点位置
     - 导航从断点继续（不是从头开始）
     - 进度条显示正确位置

5. **增益调节**

   | 现象 | 调整策略 |
   |------|----------|
   | 追踪过慢 | 增大 `OBSTRUCTION_TRACK_GAIN_M1/M2` |
   | 追踪过快，撞阻塞物 | 减小 GAIN |
   | 清除判定过早 | 增大 `OBSTRUCTION_CLEAR_FRAMES` |
   | 返回断点过慢 | 增大 `RETURN_MAX_DELTA` |
   | 返回断点过冲 | 减小 `RETURN_MAX_DELTA` 或增大 `RETURN_TOLERANCE_DEG` |

6. **验收标准**

   | 指标 | 合格标准 | 测量方法 |
   |------|----------|----------|
   | 检测响应时间 | < 1 帧 | 帧级记录 |
   | 追踪精度 | 阻塞物质心误差 ≤ 0.2 | 记录 cx/cy 偏差 |
   | 清除成功率 | ≥ 90% | 多次测试统计 |
   | 续航正确性 | 恢复后步骤 ≥ 断点步骤 | 记录步骤索引 |
   | 返回到位精度 | 误差 ≤ RETURN_TOLERANCE | 记录角度误差 |

## 故障排查

| 现象 | 可能原因 | 解决方案 |
|------|----------|----------|
| 序列无法加载 | 演示数据缺失 | 补录演示数据 |
| 机器人不动 | `active == False` | 检查模式状态 |
| 壁碰严重 | Layer 2 未生效 | 检查视觉输出、GAIN 方向 |
| 阻塞物不检测 | 视觉功能异常 | 检查 YOLO 输出 |
| 断点续航失效 | 状态机转移错误 | 检查 `RETURN_TOLERANCE_DEG` |
| 运动抖动 | 速度过快 | 减小 `PLAYBACK_SPEED` |
